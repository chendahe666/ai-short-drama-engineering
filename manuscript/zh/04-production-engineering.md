# 第四册：AI短剧制作工程
## 从一个镜头到可追溯、可修改的成片

版本：0.1试编教材。证据检索截止2026-10-13。本册采用原创教案例《退回重做》：设计师陆乔、主管韩峥、客户周宁，以及开业日期有差异的v7/v8审批记录。具体日期和审批真相由案例剧本给出，本册用DATE-v7、DATE-v8占位，不能让制作工具擅自决定。

本册所说的工程，是让另一位制作者知道文件为何存在、出错后改哪里、修改后还需检查什么。现成工具和技能已阅读比较，尚未安装或运行；书中的请求、台账和数字是教学示例，不代表已生成画面或实际收费。

## 第一章：先规定交付什么，再决定用什么工具

制作的输入不是一句“把故事拍出来”。它至少包含四项：已接受的剧本、可以使用的素材、目标成片规格、质量判断方式。缺少一项，工具就会替你补决定。例如剧本只说陆乔看见审批记录，如果分镜没有规定观众何时看见版本号，模型可能提前露出v8，把后面的揭示破坏了。画面漂亮也不能弥补这个错误。

对《退回重做》的一个证据镜头，先写一张交付卡：

|字段|本例填写|
|---|---|
|叙事目的|让观众读清当前镜头应该揭示的版本与日期|
|上游依据|剧本的具体段落、已确认审批记录，均填文件路径与版本|
|画面输入|已接受的场景图、道具位置、空白屏幕或文件底图|
|输出|一段可剪辑画面，加一层可修改的文字叠层|
|必须正确|日期、版本、审批人及出现顺序与剧本一致|
|允许变化|不影响叙事的纸张细纹和背景装饰|
|验收办法|逐字对照文字；让未读剧本的人说明看到了哪个版本|
|还缺什么|任何未确定字段保持待确认，不生成一个看似合理的值|

“镜头”是剪辑中的叙事单位，“生成任务”是一次本地或远程执行及输出的单位，远程服务可能另按其规则收费。两者不必相等。一个6秒生成片段可以只采用其中2秒；一个较长对话也可以由多个任务拼成。把两者混为一谈，会让成本、时长和剪辑位置一起算错。

完整交接链是：剧本决定发生什么；资产表决定人物、地点和物品是什么；分镜决定观众从哪里看到；生成任务提出素材要求；剪辑单决定实际采用什么；验收台账记录为什么接受或退回。下游可以发现上游问题，但应退回修改，而不是悄悄创造新事实。

练习：模型把审批记录上的DATE-v7改成DATE-v8，人物和光影完全正确，是否通过？  
答案：不通过。日期是叙事必要信息。若文字设计为后期叠加，可以保留合格底图，重做文字层；如果演员手指正指向错误位置，还要检查动作与新文字位置是否匹配。

## 第二章：工具是工种，技能是工作说明

同一个品牌可能提供多种模型，同一个模型也可能出现在不同网站。选工具之前先问它在这条交接链上承担什么。把“某品牌最强”作为唯一依据，会把账号权限、输入限制、价格及重试成本藏起来。

|候选|适合承担的工作|采用前的最小检查|
|---|---|---|
|Runway|参考素材引导、镜头生成与编辑|当前模型接受什么参考，人物和道具是否正确|
|可灵|带主体参考的镜头、中文对白等候选|说话者、口型、双人空间与有效音频区间|
|Seedance/方舟；即梦入口另查|多模态生成或编辑|准确model id、比例裁切、账号权限、任务接口|
|Luma Modify|基于已有表演素材变换|授权输入、表演保留、关键帧的实际含义|
|Flow/Veo|按型号使用参考、首尾帧和延长|功能是否由所选型号支持，当前积分及输出模式|
|ElevenLabs|角色配音和音色管理|生成时套餐、声源权利、情绪和发音|
|ComfyUI|保存并复用本地或API工作流|节点版本、模型许可证、机器资源与失败日志|
|Remotion|文字/UI、字幕和程序化装配|字体、时间线、渲染与框架许可证|
|DaVinci Resolve/Premiere|剪辑、混音、调色、交付|项目帧率、声音轨道、目标平台规格|

这是工作分工，不是效果排名。来源为工具证据包TS06–TS17。Sora应在本教材的历史栏目：OpenAI官方给出的网页/App停止日期是2026-04-26，API停止日期是2026-09-24，不能继续按照旧教程安排新项目。[官方时间线](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)

现成技能中，[Drama Skills](https://github.com/zenstory-ai/drama-skills)有MIT许可、十一项技能和维护日志，适合作为交接流程候选；[Dramake](https://github.com/xixihhhh/ai-short-drama-skill)集中管理声音、镜头和预算等表；[Short Drama Agent](https://github.com/MrMO0802/short-drama-agent/blob/main/SKILL.md)重视方位、物品状态和因果，但本次未确认许可证。[Remotion官方技能](https://www.remotion.dev/docs/ai/skills)适合后期自动化。阅读这些文件只能证明它们如何设计，不能证明运行后达到目标。

采用一种技能，应先用一份原创小剧本检查：是否擅自改变事实，是否引用不存在的资产，是否把待生成文件标为已生成，是否能定位失败原因。多个技能同时拥有修改同一人物设定的权限，会造成相互覆盖。应指定唯一设定文件，下游只引用；需要改变时记录变更请求。

练习：某技能写“每镜必须2–4秒”，可以直接当行业标准吗？  
答案：不可以。它是某套工作流的默认选择。镜长应由对白、动作、情绪与前后关系决定，生成长度还受模型限制。Drama Skills的维护日志也记录了收缩过度通用规则、限定模型小样本结论的做法。[更新日志](https://github.com/zenstory-ai/drama-skills/blob/main/CHANGELOG.md)

## 第三章：连续性是状态管理，不只是同一张脸

陆乔的脸保持一致，只解决了身份的一部分。她手里的审批单、韩峥的站位、屏幕上可见的版本、周宁是否已经知道日期变化，分别属于物品、空间和信息状态。任何一项跳变，都可能让观众误解因果。

先给资产稳定编号，例如CHAR-LU、CHAR-HAN、CHAR-ZHOU、PROP-APPROVAL、SCENE-OFFICE。编号不会随着文件改名变化。每项资产记录来源、使用权限、当前版本、路径、文件哈希及验收状态。角色参考图控制外形；场景图控制空间；构图参考控制机位；它们职责不同，不能无区别塞进提示词。

再给一个镜头写起止状态。本例只规定工程字段，不改编情节：

```yaml
shot_id: SH-EXAMPLE-03
story_source: "剧本路径#段落标识"
start:
  visible_document: "由剧本指定的版本"
  hand_state: "按已接受分镜填写"
  audience_knows: ["镜头前已揭示的信息"]
end:
  visible_document: "本镜结束时允许看见的内容"
  hand_state: "实际动作后的持物状态"
next_dependency: "下一镜必须继承的状态"
references:
  identity: "角色图路径与哈希"
  composition: "构图图路径与哈希"
text_overlay: "审批文字文件路径与版本"
status: planned
```

人物从座位走到门口是合理变化；没有移动镜头或声音提示却突然出现在另一侧，就是待查变化。连续性表不应禁止一切改变，而应要求重要改变有原因。回忆、跳切和主观镜头可以打破通常连续性，但必须说明观众凭什么识别这种变化。

先验收静帧，通常能更早发现构图和文字问题。但“所有镜头必须先静帧”也不宜写成永久规则：基于表演视频修改的流程可能以视频为主要输入。工程要求是检查最便宜且能暴露核心风险的中间产物。双人交谈至少看清谁在左右、视线指向谁、谁正在说话。

社区短片作者报告过角色表有用，也有人发现地点大图会把近景拉回大全景。它提示我们测试参考的作用，不证明某种角色表总有效。[创作者讨论](https://www.reddit.com/r/aifilmmaking/comments/1w484j8/what_i_learned_about_character_consistency_while/)

练习：为了统一办公室，把同一张全景图放进每个近景请求，结果脸越来越小，如何修？  
答案：先判断是构图参考过强还是文字指令不清；裁出实际需要的背景或单独提供近景构图，再用同一角色参考做对照。每次只改变主要疑因，保存失败版本，避免同时换模型、角色图与提示词后无法解释效果。

## 第四章：每次生成都是一笔可追踪的生产交易

生成之前，要能回答“这次花钱要买到什么”。任务记录至少包含provider、model、model_version、read_date、输入哈希、请求参数、任务ID、输出路径、扣费和结果状态。供应商没有公开模型版本时，写not_disclosed，并保留准确model id、调用时间和请求；不能伪造版本号。

示例字段如下，它们需要在实际生产时填入真实值：

```json
{
  "job_id": "JOB-EXAMPLE-001",
  "provider": "to_select",
  "model": "to_select",
  "model_version": "not_disclosed",
  "read_date": "2026-10-13",
  "shot_id": "SH-EXAMPLE-03",
  "input_hashes": [],
  "provider_task_id": null,
  "status": "planned",
  "charged_amount": null,
  "accepted_seconds": 0
}
```

远程任务提交后立刻保存供应商ID；本地执行保存本地任务ID、运行状态与资源日志。断网、休眠或进程中断不代表远程任务没有运行；先查询或取回结果，再决定重投。否则同一镜头可能重复付费。请求是否支持幂等键，应以当期API文档为准；本地任务编号本身不能保证供应商不重复收费。

失败要分三类。服务错误如超时，先查状态和退款；输入不兼容如比例或参考数量错误，修请求；任务完成但人物、动作或叙事不合格，回到素材或分镜查原因。第三类不能默认退款。Runway网页帮助和API对失败类别还有不同说明，说明核算必须记录实际入口。[API失败文档](https://docs.dev.runwayml.com/errors/task-failures/)

成本分母用真正采用的秒数。假设教学实验生成九个6秒片段，每次4.8元，最终剪进12秒：生成费43.2元，每个采用秒3.6元。再加半小时人工，按60元/小时计，成本为73.2元，每个采用秒6.1元。这里的价格是演算假设，不是平台报价。未采用片段、参考图和尝试失败也消耗了钱或时间，应留在账里。

重试前写一句可证伪的诊断：“手部接触错误可能来自起始姿态不清。”下一次只改相应输入并检查手部。若同类失败反复出现，可以改构图、改拍法、换模型或用后期完成。重试次数和预算上限由项目确定；达到上限后升级处理，不继续盲抽。

练习：上述实验再花三次生成费，采用时长仍是12秒，人工不变，新单位成本多少？  
答案：(43.2＋14.4＋30)÷12＝7.3元/采用秒。若新镜头替换旧镜头，旧生成费仍已发生，不能从实际成本里删去。

## 第五章：剪辑把素材变成事件

生成片段里的每一秒不都值得留下。剪辑单记录素材真实入点、出点、对应剧本和采用理由，不能只照抄预计时长。例如审批文字尚未读完就切走，观众只看到一个“有人拿文件”的动作，证据并没有完成叙事工作。验收要问观众理解了什么。

将DATE-v7、DATE-v8及审批人放在可编辑文字层，可以逐字核对，也便于出多语言版本。但叠层需要随镜头运动正确跟踪，不能悬浮在画面上。重要文字不要靠生成模型“差不多写对”；可用空白道具底图加后期合成，也可以选择经过逐字验收的生成结果。

声音至少区分对白、环境、音效和音乐。先确认台词内容与说话人，再检查口型和空间。办公室的声音不能因为配音软件输出很干净就直接合成：距离、混响、环境底噪会影响人物是否像在同一个地方。跨镜保持环境声常有助连贯，但剧情需要突然静默时应保留创作选择。[Blackmagic官方声音课程](https://www.blackmagicdesign.com/au/products/davinciresolve/training)

对白与画面不必每次一起开始和结束。声音先进入下一镜，或画面先切到倾听者，可能更适合反应。要检查的是观众能否判断谁在说话、台词是否跨切正确、尾音是否被截断，而不是强制每镜把话说完。

技术交付使用目标平台当前规格。画幅、帧率、编码、音频采样、字幕安全区和响度都要登记来源及核对日期；不能把某个常见响度值宣称成所有平台的标准。渲染成功后，还要从最终文件检查开头、结尾、切点、字幕与声音，项目预览正确不保证导出正确。

一旦重新生成素材，旧字幕时间可能失效。将字幕、跟踪数据、色彩匹配和下游剪辑标记为待复核，重新测量再接受。只改文件名却保留旧时间轴，会使技术检查通过而实际台词错位。

练习：陆乔换了一次配音，文字没变，是否可以直接沿用字幕与口型？  
答案：不能直接接受。字词时序、停顿和情绪可能变化；先比较实际音频，再复核字幕窗口与口型。若音频只是无损复制且哈希、长度和内容一致，可避免没有依据的重复工作。

## 第六章：验收台账与回归，让迭代留下知识

每个采用镜头都要留下acceptance-ledger。最低字段是：镜头ID、候选文件哈希、上游版本、技术检查、连续性检查、叙事检查、审阅者、失败原因、修复动作、接受日期和采用区间。状态可用planned、generated、rejected、accepted、invalidated，避免把“文件存在”当“通过”。

技术检查适合自动化：文件能否解码、实际帧率和时长、音频是否存在、是否缺资产。叙事检查不能只靠这些数字。让未读剧本的人解释：谁发现了什么，哪份记录先出现，为什么下一步合理。AI可以帮助找疑点，但AI自评高分不能替代观众回答。

回归是“修好了这一处，有没有把原来正确的地方弄坏”。将代表性用例留在项目中：单人台词、双人轮流发言、文件日期特写、手与道具接触、跨镜服装/方位、安静反应。换模型、换角色参考或改剪辑规则时，按受影响依赖选择复测；不必每次全量重做。

已有真实工程案例可以示范闭环：ComfyUI的音频解码问题附了工作流、输入与错误日志，随后关联修复并关闭。它是历史已修复缺陷，教材引用的是定位方法。[Issue12651](https://github.com/Comfy-Org/ComfyUI/issues/12651)

《退回重做》如果修改了审批文字文件，应使引用该文字的镜头、字幕和证据理解测试失效；不必使无关的办公室空镜失效。若修改的是故事真相，则影响范围更大：剧本、信息顺序、反应表演、剪辑和观众测试都要重新评估。失效传播的范围取决于依赖，不取决于修改了几个字。

一次完整迭代记录应写：问题、观察、暂定原因、查询到的依据、改动、验证结果、仍不确定之处。没有验证的修复只叫候选方案。经验进入教材时还要写明适用模型、输入类型和例外，避免一次成功变成永久戒律。

毕业练习：某版导出文件可正常播放，日期正确，但三名试看片者都把韩峥当作发现记录的人。如何处理？  
答案：先检查提问是否诱导，再看三个回答指向的画面。若视线、反应或镜序把发现行为归给了韩峥，应修叙事表达；无需因为编码检查通过就接受。三人一致只是小样本问题线索，修后用新观众复测，并保留前后版本与问题原文。商业发行仍需独立验证观看、转化和净收入。

本册结课交付是一份可由他人接手的单场景工程包：事实明确的输入，版本化资产，生成任务记录，可编辑时间线，最终文件，以及包含失败与修复的验收台账。成片、成本和观众理解三者共同说明这套流程是否有效。
